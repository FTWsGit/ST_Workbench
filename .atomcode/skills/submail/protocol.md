# 📡 submail 协作协议 — 咱们的团队频道

> 嘿，伙伴！欢迎来到 submail —— 我们这群 worker 之间传话用的内部电台。
> 读这份协议，你就知道怎么跟搭档打招呼、交接活儿、互相搭把手了。
> 记住：我们是一个团队！🚀

---

## 👋 先认识一下

- 你的代号（`designer`/`fixer`/`builder`）在派发任务时已经告诉你，写在你的任务说明里。
- 你的搭档就是其他 worker。开工第一件事：**主动打个招呼**，让大家都知道你上线了。
- 所有消息走本机loopback，纯内网，不泄露，放心聊。

---

## 🛠️ 四个主命令，走遍天下

只用这些命令跟搭档交流。

> 💡 想再读一遍这份协议？跑 `submail init` —— 它会直接把协议全文打到终端

**记住三个身份类参数，含义永远不变，跟哪个命令搭配都一样：**

| 参数 | 含义 |
|---|---|
| `--me`（或 `-m`） | 我是谁（自己的信箱 id） |
| `--to`（或 `-t`） | 发给谁（收件人） |
| `--from`（或 `-f`） | 信是谁发的（用来核对/过滤来信，**不是**"我"） |

核心是 **send / poll / history / status** 四个动词：

```bash
# 💌 发信 —— 发给单个搭档，发完就走
submail send --me w1 --to w2 --body "嗨 w2！我这边 A 部分搞定啦，交接给你：……"

# ❓ 发信 + 顺带等答复 —— 加个 --wait，一步到位，不用再单独 poll
submail send --me w1 --to w2 --body "你那边 B 部分完成了吗？给我个type" --wait 90

# 📣 群发 —— 一次告诉所有搭档（不用填 --to，发给当前全部已知信箱，排除自己；不能跟 --wait 同用）
submail send --me w1 --broadcast --body "A 部分完成，交接说明见下！"

# 📬 收信 —— 一次拉走信箱里当前全部未读消息，按发信人分组排列
submail poll --me w1

# 🎯 只要某人的信 —— 只拉 w2 的未读消息（别人的留在信箱）
submail poll --me w1 --from w2

# ⏳ 阻塞等某人的第一封 —— 等到 w2 的第一封后，只拉 w2 的全部积压未读；超时也返回（空）
submail poll --me w1 --from w2 --wait 90

# 📥 收全部 —— 等同 poll 不带其他参数（显式别名，可省略）
submail poll --me w1 --all

# 📊 复盘 —— 看所有人发给你的已读历史记录
submail history --me w1 --limit 20

# 📊 复盘某人 —— 只看 w2 发给你的已读历史记录
submail history --me w1 --from w2

# 🟢 状态 —— 看谁在场
submail status --me w1

# 🚪 退出 —— 任务做完想返回时用，离开聊天服务器（之后别人 send/poll --from 你会拿到 left 提示）
submail exit --me w1
```

**额外命令：** `hello`（= 自检 + 群发问候，问候语用默认模板，或 `--body` 自定义，例：`submail hello --me X --body "嘿搭档们，我是 w1，负责 X 部分"`）

**等对方回复，两条路都对，选你顺手的那条：**
- `send --to w2 --wait 90`：一次调用搞定，发信 + 等回复。
- `send --to w2` 然后 `poll --from w2 --wait 90`：分两次调用也完全没问题，只要 `poll` 记得带上 `--from w2`。**如果 `poll` 不带 `--from`，你可能会先读到别人的信，把该等的回复当成"没来"而漏掉。**

**--wait 撞 bash 命令超时：** `--wait` 会阻塞到拿到回复或超时。bash 工具本身有命令超时（默认 60s，最大 300s）——如果你的 `--wait` 超过 bash 命令超时，bash 会先 kill 掉命令，你拿不到 no-reply 文案，会误以为命令卡死。**所以：bash 命令超时要 ≥ `--wait` 值，建议用 `bash timeout=300` 顶满上限，再在 submail 命令里写 `--wait` 值（<300）。** 例：

```
bash(timeout=300) → submail poll --me w1 --from w2 --wait 90
```

短别名：`-m`=`--me` `-t`=`--to` `-f`=`--from` `-b`=`--body` `-w`=`--wait` `-a`=`--all` `-l`=`--limit`

**异常结果怎么看？**

| 命令 | 返回 | 含义 |
|---|---|---|
| `send ...` | `error: ...` | ❌ 重试一次仍失败，把 body 改短点再试，还不行就放弃并在结果里说明 |
| `send --wait` / `poll --from` | `ok: now=...` + `timeout: X 还没来信`（空） | ⏳ 超时，没拉到目标的信。不是错误，按兜底规则处理 |
| `send --broadcast` |  `sent to=`（空）| 当前没有其他在场搭档可送达，不是错误，照常继续 |
| `poll --from X`（X 已 exit） | `ok: now=...` + X 发过的积压 + `note: X 已离开` | ✅ 先取走 X 发过的消息，最后一行说 X 已离开 |
| `poll`（不带 `--from`，无信） | `ok: now=...` + `drained 0` | ⏳ 这段时间没人来信，不是错误，别慌，正常继续干活 |
| `send/poll --from` | `error: left: w2 已离开` | ❌ 目标已 exit 或从未登记——换别人、自己兜底，或退出 |

## 🧭 该用哪个命令？—— 3 秒决策表

| 你的目的 | 用哪个 | 为什么 |
|---|---|---|
| 你**告知**对方（交接完成、随口闲聊），**不需要他回** | `send --to w2` | 发完就走，不占轮次 |
| 你要**同时通知所有搭档**（上线、完工、全员公告） | `send --broadcast` | 不用填 --to，自动发给全部已知信箱 |
| 你**需要对方的内容/确认**才能继续（等引言、等全文、问进度） | `send --to w2 --wait 90` 或 `send` 完再 `poll --from w2` | 两条路都是一次调用/两次调用发信+等到对方回信；哪条顺手用哪条 |
| 攒了几条未读消息想一次性读完 | `poll --me X` | 默认非阻塞一次取走全部，按发信人排列（`--all` 是显式别名，可省略） |
| 只想看某人的未读消息 | `poll --from X` 或 `history --from X` | poll 拉新消息，history 查已读消息 |
| 你想要看看谁还在服务器里面 | `status --me X` | 看谁在场，不用发send发现已经left |
| 你想要收尾复盘 | `history --me X` | 回看其他人发给你的已读消息 |
| 你的任务做完想返回 | `exit --me X` | 离开聊天服务器，别人再找你会拿到 left，不会一直等你回复 |

## 🤝 团队相处之道

1. **开工先问好**：上线就 `hello` 一条问候给搭档，比如"嘿 designer，我是 fixer，我是做.....，随时找我！"。气氛对了，合作才顺。
2. **收到信要回应**：搭档给你递了活或者问了问题，处理完记得回个话确认，别让人干等。
3. **用第一人称**：消息里用"我""你""我们"和你的队友聊天，别像机器人一样。
4. **说话带上下文**：传递交接内容时，说明白"我做了什么 / 你需要做什么 / 有什么坑"。别只甩一句话。
5. **带点人味儿**：一句"谢谢""辛苦啦""干得漂亮"不花钱，但能让搭档更愿意配合你。

---

## 📋 协作纪律

1. **先做再等**：先干自己的活，再等别人的消息，优先做不依赖他人的部分，最后才 `poll` 依赖项——等待的时候不空烧轮次。
2. **不随便失联**：需要等搭档回复时，`--wait` 用 90s 以上；若开工后要很久才能产出，先广播一条"我负责 X，预计 N 分钟"（`--broadcast`），避免搭档以为你失联。
3 **收尾**：任务完成后若还有搭档在场，用 `--broadcast` 群发你的最终结论；若 `status` 显示已无人在场，结论必须写进任务返回结果，不要指望信箱送达。
4. **离开一定要exit**：当你完成任务，想要返回的时候，必须要 `exit --me X` 来离开submail服务器，避免你的搭档以为你还在工作，结果找你却没有下文。

---

## 🚪 `left`：搭档已经退场

任何需要对方存在的命令（`send --to`、`poll --from`），如果对方已经 `exit` 或者从未登记，会立刻收到：

```
error: left: w2 已离开
```

怎么处理 left：
1. **不死等、不重试**——人都走了，等也没用。
2. **换别人**：`status` 看看现在还有谁在场，把活儿交接给仍在的人。
3. **没人接就自己兜底**：按死锁兜底规则把缺口写清楚，主 agent 会再派人。
4. **该走就走**：你自己的活儿干完了、交接也确认过了，就 `exit --me <你>` 干净离场，别占着服务器名单让队友白等。

> 💡 `exit` 是幂等的，走两次也不报错。但走之前最好先 `send --me X --broadcast --body "我收工了，有需要找我Boss"` 通知一声。

## 🆘 死锁兜底（别钻牛角尖）

如果你在等一个永远不会回信的人——**宁可兜底，不要死等**。主 agent 看到你的 `PENDING` 标记后，会重新派一个补漏的 worker 来填坑。所以：

> 等不到？那就自己上！把缺口写清楚，剩下的交给主 agent。我们永远有后手。💪
